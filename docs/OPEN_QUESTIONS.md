## 2026-10-29 去掉封顶（用户决定）

用户："不需要记分的，就记数值就行了，不要封顶"。原因：Claude Code 和 Codex 一起跑，当天 13:38 就到了每日 6 人日，之后的活全记 $0，桌宠和仪表盘看起来没反应。去掉了单回合 6 小时、每日 6 人日、每周 30 人日三个上限（assets/scoring.toml v3.0 只剩 `minutes_per_day = 480` 这个单位），历史用 `dango rebuild` 重算，总数只升不降。黄金回合"huge refactor"从 360 分钟 / $392 变成 2,396.66 分钟 / $2,611.56。**待观察**：没有单回合上限后，一个异常长的回合（几百次编辑）会记很大的数；要不要只对明显异常的回合提示，看实际数据再说。

## 2026-10-29 v5：经济杠杆（用户决定）

000000. 杠杆从"时间杠杆"改成"经济杠杆 = 产出 $ ÷ 模型花费 $"，模型花费按每个回合的 token × 官方 API 单价（见 DESIGN.md v5）。本机：Claude Code $8,631 ÷ $387 = 22.3x，Codex $3,649 ÷ $253 = 14.4x（2026-10-29）。**待定 / 未覆盖**：
   - 用订阅的人实际付的不是 API 价。要不要让用户填月订阅费，另算"按订阅的杠杆"。
   - 没有单价的模型只计 token 不计钱：`codex-auto-review`（Codex 审查线程）官方页没列。Fast 模式（`@fast`）、美国区域 1.1 倍、Batch 半价都没算（本机日志里没有 fast）。

   - 价格会变：`model_prices.toml` 需要定期对照官方页更新。

## 核对官方文档后的改动（hooks 文档，2026-10-28）

5. **结算框不能走 stderr**：exit 0 的 hook stderr 不显示给用户。改为同步 Stop hook 输出 `{"systemMessage": "<框>"}`——显示给用户、不进模型上下文。
6. **async hook 必须什么都不打印**：async hook 的 stdout 会在下一回合交给 Claude。
7. **子 agent 工具名是 `Agent`**（matcher 写 `Agent|Task` 兼容旧版）。
8. **失败的命令走 `PostToolUseFailure`**，不走 PostToolUse。插件多注册了这个事件（只匹配 Bash），否则拿不到“测试失败”，拆弹专家 / 绿灯 / 一行定乾坤都无法判定。
9. 回合 ID 用 hook 公共字段 `prompt_id`；transcript 里对应 `promptId`。

## 实现中做的取舍（可改）

10. **spool 按 UTC 日分文件**（`spool/events-YYYYMMDD.jsonl`），而不是单个 events.jsonl 再轮转——避免重命名时与正在追加的 hook 竞争。保留 7 天的规则不变。
11. **晨鸟 T02 = 5:00–5:59 开始的会话**。SPEC 写“6 点前”，会与夜猫子（0–5 点）重叠。
12. **一口气 / 马拉松用活跃分钟**，不是墙钟时长（会话挂一夜不算）。
13. **职业卡 ML 工程在 5.1 没有映射规则**，导致“全栈”“万能钥匙”永远拿不到。加了路径规则：`ml/ models/ training/` 目录、`train*.py`、`.pt .onnx .safetensors .h5 .ckpt`。
14. **bugfix 关键词“修”收窄为“修复 / 修一下 / 修好”**——“修改”太常见，会把大量普通请求判成修复。
15. **个人纪录的庆祝加了门槛**（“稀有才有情绪”）：旧纪录至少为 单日 0.5 人日 / 单会话 0.25 人日 / 杠杆 3x / 连续 5 天，且新值在显示精度上可见地更高，每项每天最多一次。否则安装第一周几乎每回合都在“破纪录”。（待定：门槛值）
16. **免打扰期间只推迟大庆祝**。权限等待后 60 秒内回合结束时，结算框照常出现（它是 agent 停下后才出现的，不打断任何东西）。
17. **杠杆成就 L01 只在 SessionEnd 评估**（按 SPEC 5.4）。被直接杀掉、没有 SessionEnd 的会话拿不到 L01；回填会为已结束的历史会话补 session_end。
18. 考古学家用 `git log -1 --format=%ct` 取文件最后提交时间，在 async hook 里跑，大仓库可能慢（不阻塞 agent）。
19. 通过 Bash（sed、heredoc）改的文件不计入改动量。新版 Claude Code 的 `tool_response.bashEditDiff` 可以补上，下一步可接。
20. 回填只读 `~/.claude/projects/**` 的 transcript，没读 `history.jsonl`（transcript 已包含全部 prompt）。

## 真实数据校准结果（作者本机历史，22 个 transcript）

21. **分类器 v1 的 other 占比 78%**（105 个回合里 82 个），远超 SPEC 19“超过 25% 再做 v2”的线。主要原因：大量非编码类请求、短 prompt（“继续”）。**待定**：先扩关键词表，还是直接做 v2。
22. 校准：每活跃小时 **0.385 人日**（目标 0.4–0.8，略低）；会话杠杆率均值 **4.6x**（目标 3–10x）。样本小，先不动常数。
